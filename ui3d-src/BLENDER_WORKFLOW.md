# Blender authoring and round-trip

Tested with **Blender 5.2.1 LTS** installed at
`C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`.
Earlier Blender versions have not been tested. The bundled sample GLB was
genuinely exported with this executable, not generated by a Three.js substitute.

## Reproduce the sample

From `ui3d-src`:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python tools\blender-roundtrip.py -- tools\roundtrip-output
npm run roundtrip
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python tools\test-addon.py
```

The first script creates the scene from `blender-addon/sample_device.py`, writes
an expected report from Blender transforms/UVs, and exports `device.glb` with
extras, Y-up conversion, cameras and NLA tracks. The Node script actually loads
it with GLTFLoader and compares names, world position/pivots, world quaternions,
scale, camera types, plane UVs and named clips. The genuine report is bundled
as `public/devices/classic-demo/roundtrip-report.json`.

The check passed for 25 named objects, two cameras and three clips. Camera world
rotation comparisons use the exporter-specific camera correction (`basis × world`
instead of `basis × world × inverse-basis`); the script tests camera quaternion,
type and position, while browser checks verify the selected camera view.

## Local axes and origins

Use an Empty as the control root. Position its origin at the axle. Parent cap,
body and pointer meshes to it; their local transforms stay authored. Make display
planes face Blender local +Z, keep UVs, and place them slightly above the body.
Do not apply control names to independent decorative roots.

The standard Blender exporter bakes basis conversion into node transforms and
geometry: **X → X, Y → −Z, Z → Y**. In the real fixture the cylinder's thin axis
and pointer offsets confirm local Y in glTF corresponds to Blender Z. A 90° turn
about that converted axis preserves the pointer height and moves it around the
panel; this is checked by `roundtrip.mjs`.

The runtime recognizes `asset.generator` containing `Blender I/O` and converts
configured local axes once. It preserves every imported node/parent transform
and multiplies the captured root quaternion by a local rotation. Procedural
geometry instead has a basis-changing parent; its local Z axis is retained.
Do not blindly apply another global scene rotation. Nonstandard exporters,
manually reoriented hierarchies and exports without that generator marker require
fixture verification; their axes currently use glTF local space directly.

## Add-on installation and use

Install the bundled `blender-addon/radionics_device.zip`, or zip the
**radionics_device folder itself**, including its files; install the ZIP
from Blender Preferences > Add-ons > Install from Disk and enable Radionics
Device. The Sidebar (`N`) has a **Radionics Device** tab.

1. Edit device ID/name/version, initial-state JSON and camera names.
2. Select a control and edit type, optional state ID, Blender-local axis,
   angles/range/step/default, drag sensitivity and wrap. Apply object properties
   writes portable custom extras. For display/LED objects configure source/when
   and display styling, then Apply. Existing extras remain available in Blender's
   native Custom Properties panel.
3. Add rate groups, enter ordered member state IDs, and move rows up/down. Use
   `main` with `knob10_1`, `knob10_2`, `knob10_3` for the sample.
4. Validate Device writes a **UI3D Validation** text with errors and warnings.
5. Select an export folder. Export Device writes `device.glb` + `device.json`.
   Import the pair into the app or copy it over the bundled startup entry.

The smoke test passed registration, property editing, member reordering, valid
export, suffix rejection and unregistering. It exercises real Blender operators.

## Honest first-version limits

The add-on is functional but partial. No sophisticated initial-extras editor
sync, rate-member removal UI, animation-mapping UI, complete runtime-equivalent
expression parser, exhaustive pivot/UV quality heuristics or JSON Schema engine
is shipped. Runtime validation remains authoritative. Optional material
animation export/loading via `KHR_animation_pointer` has not been verified;
required unsupported extensions are rejected. Use runtime emissive bindings
for LEDs and ordinary transform clips on separate objects.

For mobile aim below 50,000 triangles, a few materials, textures <=1024² and
models below 5 MB. These are authoring targets, not measured device guarantees.
Draco/Meshopt are supported with local decoders; KTX2 is not enabled.
